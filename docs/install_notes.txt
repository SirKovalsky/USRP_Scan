0. ИТОГ КРАТКО
--------------------------------------------------------------------------------
Проблема была НЕ в UHD-драйвере, а в отсутствии Python-модуля `uhd` в .venv.
Драйвер UHD установлен и работает:
    UHD_PKG_PATH = C:\Program Files\UHD
    uhd.dll      = C:\Program Files\UHD\bin\uhd.dll
    найдено устройство: B210, serial 8004731, name Zhixun-wireless

Причина сбоя `pip install uhd==4.10.0.0`:
    wheel uhd требует numpy<2.0, а в venv был Python 3.13, где готовых
    wheel'ов numpy<2 НЕТ -> pip полез собирать numpy 1.26.4 из исходников
    -> упал, т.к. нет компилятора C (cl.exe / MSVC).

Решение: пересоздать .venv на Python 3.12, поставить numpy<2, затем uhd.
Сделано и проверено. Ниже - детали, команды и правки по проекту.

--------------------------------------------------------------------------------
2. КОРНЕВАЯ ПРИЧИНА
--------------------------------------------------------------------------------
* uhd==4.10.0.0 (метаданные) требует: numpy>=1.11,<2.0
* Python в venv был 3.13.0. NumPy 1.26.4 поддерживает Python только 3.9-3.12,
  поэтому wheel `numpy-1.26.4-cp313-...` не существует.
* pip, не найдя wheel, скачивает numpy-1.26.4.tar.gz и собирает из исходников.
* Для сборки нужен компилятор C (MSVC / Build Tools). Его нет -> ошибка.
* Итог: на Python 3.13 модуль uhd НЕ ставится штатным `pip install`.

Матрица совместимости (важно для правок в основной сессии):
    Python 3.10/3.11/3.12 -> есть wheel numpy<2 и uhd (cp310/cp312) -> OK
    Python 3.13           -> нет wheel numpy<2, uhd есть cp313        -> FAIL
    Python 3.14           -> нет wheel uhd                            -> FAIL
Вывод: поддерживаемый диапазон для Windows = Python 3.10..3.12.

--------------------------------------------------------------------------------
4. ВРЕМЕННЫЙ ВАРИАНТ БЕЗ СМЕНЫ PYTHON (fallback, не рекомендуется)
--------------------------------------------------------------------------------
На Python 3.13 можно поставить привязки в обход зависимости:
    pip install --no-deps uhd==4.10.0.0
Тогда wheel cp313 встанет поверх уже стоящего numpy 2.x. Импорт РАБОТАЕТ и B210
даже находится, НО numpy 2 печатает при каждом старте:
    "A module that was compiled using NumPy 1.x cannot be run in NumPy 2.x..."
Это предупреждение о потенциальной нестабильности/креше. Поэтому выбран
переход на Python 3.12 (пункт 3). --no-deps использовать только как костыль.

--------------------------------------------------------------------------------
6. ЗАМЕЧАНИЯ ДЛЯ ОСНОВНОЙ СЕССИИ
--------------------------------------------------------------------------------
1. UHD обязателен: `import sdrscan` теперь падает с ImportError, если модуля
   `uhd` нет. Это осознанно (fail-fast). Если нужно более дружелюбное
   сообщение вместо traceback - обсудить отдельно.
2. Строки `[INFO] [UHD] ...` и `[INFO] [B200] ...` идут в stderr - это НЕ
   ошибка; PowerShell просто подсвечивает stderr красным.
3. Если пользователь ставит на Python 3.13 - сначала пересоздать venv на 3.12.
   `--no-deps` не рекомендовать.
4. requirements.txt намеренно НЕ содержит `uhd`: его wheel привязан к версии
   Python и (на Windows) требует UHD-инсталлятора. Ставить отдельной командой.
5. На Linux всё иначе: uhd ставится apt-пакетом python3-uhd, venv создаётся с
   --system-site-packages. Правки numpy<2 касаются только Windows-ветки.
